# 基地备用账号密码设置

账号显示名称：**基地备用**。权限角色：**基地成员**，使用基地成员默认页面读取权限。共享账号不绑定某位员工，个人请休假、加班及其他业务修改请使用本人账号。

1. 将工具解压到系统安装目录，保留 `scripts` 文件夹结构；系统目录内应已有 `.env`。
2. 双击 `scripts/set-site-member-backup-password.cmd`，输入两遍新密码。密码为 8～256 个字符，须与其他备用角色密码不同。若工具未找到系统目录，会提示填写包含 `.env` 的安装目录。
3. 安装包含此账号的新包。安装器正常启动应用后，在统一登录窗口点击底部的“备用登录”，输入刚设置的密码，登录姓名应显示“基地备用”，权限显示“基地成员”。

工具仅保存随机盐 `scrypt` 哈希，不生成默认密码或明文密码文件。它只修改 `LOCAL_SITE_MEMBER_PASSWORD_HASH`，并清除 `.env.local` 中同名的旧覆盖项，保留其他配置；文件切换失败时恢复原字节。工具不会停止、启动或重启服务。

若在安装新包之后才设置密码，需要按系统既有的正常重启流程使新配置生效。修改此密码并重启后，原备用账号会话失效。

若提示“基地备用账号已有配置页设置”，说明管理员已通过配置页维护过该账号。为保留管理员的停用、删除及授权版本设置，脚本会停止且不修改文件；请由管理员在配置页编辑“基地备用”，设置新密码及账号状态。不要手改权限台账。

运行需要系统已有 Node.js 24 或以上版本。此工具不修改人员多维表，不发送审批、卡片或通知，不启用飞书回调。

验证范围：底层 Node 设置、重复密码拒绝、覆盖项处理及原字节回滚已自动验证；PowerShell 5.1 语法已验证。自动执行交互式 SecureString 输入验证被工具自动审批拦截，因此完整现场交互输入仍需操作人员执行确认。

工具文件应同时包含：

- `scripts/set-site-member-backup-password.cmd`
- `scripts/set-site-member-backup-password.ps1`
- `scripts/set-site-member-backup-password.mjs`
- `scripts/reset-all-access-passwords.mjs`（共用文件写入工具）
- 本说明文件

附件内不应包含 `.env`、权限台账、日志、账号密码或任何运行数据。
